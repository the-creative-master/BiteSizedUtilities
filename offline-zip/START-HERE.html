From a folder  What works, and what is waiting on a server

A page opened off the disk gets an origin the browser will not trust, and from one it refuses three things: an ES module, a worker, and a fetch of the file sitting next to it. That is not a broken download and there is no setting to flip — it is the same rule everywhere, for every site.

The folder build works around the first of those, which is why the kitchen opens at all. The other two are why a few things stay asleep until the folder is served:

Want the rest? One double-click — optional

Serving the folder over http://localhost lifts every one of those refusals at once, and the same index.html then loads the full site instead of the folder build. Pick your machine:

If you are onDo this
Windowsdouble-click start-server.bat
macOSdouble-click start-server.command
Linuxrun sh start-server.sh in this folder
Any of them, by hand
cd path/to/this/folder
python3 -m http.server 8123 --bind 127.0.0.1
then open http://localhost:8123/index.html

All three scripts need Python 3, which macOS and most Linux installs already have and Windows gets from python.org. They serve this folder to your own machine only, on port 8123, and they stop when you close the window. None of this is required to use the kitchen — it is the price of the parts a browser will not run off the disk.

Three honest caveats

  • Threaded WASM will run one thread deep. Shared-memory threads need cross-origin isolation headers, which python -m http.server cannot send. The site detects that and drops to a single thread, so the runtimes and Waffle AI still work — some of them just take longer.
  • A phone or tablet cannot run the local server without a third-party app. It can still open index.html and get the kitchen and the games that work from a folder — but a tablet's file manager chooses which browser opens it, and some of those refuse local files outright. If this folder came from the site you were already visiting, the site's own offline mode is the better route there: visit it once while online and it keeps working after.
  • This folder is a snapshot. The zip is rebuilt on every deploy of the site, so a folder this old may be behind the live one. Nothing in it phones home to check.
